## Phase 2 — Backups at scale, SSL/Domains, Multi-server

- [x] **2.1 Scheduler (rq-scheduler) + backup schedules & retention sweeps.** `Schedule` model + migration `d3f5a1c7e9b2` (target_type/id, action_name, cron|interval, timezone default `Asia/Dubai`, enabled, next_run_at, last_run_at, last_run_job_id, retention params). rq-scheduler process (`app/workers/scheduler.py`, `make scheduler`) registers a single recurring tick; each tick sweeps due schedules and enqueues real `CommandJob`s through the JobRunner (golden rules 2/3) — a scheduled fire is locked, audited and streamed exactly like a hand-launched job. Reuses `site.backup` (1.11); adds `backup.retention_sweep` (dry-run kept/removed log first, `rm -f` only paths under `private/backups/`, **never the newest/only backup**, then delete the rows). CRUD `/api/schedules` (Admin/Developer manage via `schedule:manage`, Operator run-now via the action's own permission, Read-only view) + enable/disable + run-now → job. **Missed-run policy:** the scheduler fires a due schedule once and recomputes `next_run_at` forward from now — a scheduler outage yields one catch-up run, never a backlog stampede; disabling makes it non-due. Schedules page (list-first per B4.12: target, action, cadence, next-run rel+abs-on-hover, last result, enabled toggle, EmptyState); calendar deferred to 3.5.
